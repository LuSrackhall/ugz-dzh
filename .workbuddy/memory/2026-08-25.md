## 打印版数据区边框/数字大范围丢失修复（6855c97）【已废弃，见下条】
- **根因**：8af3cf0 为修页码"100/200"回归，把 transformSheet 的 switch 中 `val!="" && isNumericAmount(val)`（数值任意行拆位）分支**整体删掉**，只留 `数据区空值拆位`。但下一个 `case sid != 0`（amountEdgeStyle 仅继承边界）**无 isDataRow 守卫**，于是数据区所有"有值金额格"落入该分支——不写数字、不生成分组竖线 → 整片数据区边框/数字异常，GL+ML 同受影响。
- **修法**：拆位条件复原为 `(数值 && isDataRow) || (空值 && isDataRow && 有样式)`。非数据区数值（Front 逻辑页码"1"/"2"）仍走文本标签分支，`!isDataRow(r)` 拦截，不会重新拆成"100"。
- **关键教训**：修一个分支的回归，绝不能删掉另一个正确分支；应把"任意行"收敛为"数据区"而非删除。switch 顺序里 `amountEdgeStyle`（仅边界）必须永远排在"数据区拆位"之后，且自身不应吞掉数据区有值格。
- **验证手段**：用 test/e2e/test_data + `init -s 2026-01` + `generate -f` 生成 fixed/buggy 两版打印 xlsx，openpyxl 对比非空格数(+30~+536)与内部竖线(+283~+1372)；再 grep 字面"100"/"200"=0 确认页码回归未复发。

## 用户否决 8af3cf0 + 6855c97，改按"单元格类型"判别（446be5c，最终方案）
- **用户裁决**："放弃 8af3cf0 与 6855c97 两次提交的修改，没改对地方"。行区(isDataRow)启发式方向被否。
- **真根因（本次定位）**：ML Front 逻辑页码 `writeMLPageNumLayout` 用 `fmt.Sprintf("%d", num)` 写入 → 查看版里是**字符串类型** `'1'/'2'`，恰好落在金额列（明细13，col27=AA32）。而所有真实金额都是**数值类型**（GL=General 格式数字、ML=#,##0.00 格式数字）。`isNumericAmount('1')` 把字符串'1'当 1 元 → 拆成元1角0分0="100"。
- **判别依据（已验证 100% 干净）**：excelize `GetCellType`：数值=CellTypeUnset(0，无 t 属性)、字符串=CellTypeSharedString(7)/InlineString(5)/Formula(4)。全表扫描：金额列里唯一"字符串数值"就是页码；月/日/凭证号等字符串全在非金额列。
- **实现**：`readSheetMeta` 对 val!="" 的格记 `isStr`（GetCellType）；switch 中 `val!="" && cell.isStr` → 文本标签整段保留+合并；`(val!="" && !cell.isStr) || (空值 && isDataRow && sid!=0)` → 拆位。`isNumericAmount` 移除。**与行区/金额格式无关，GL/ML 通吃**。
- **验证**：e2e 2026-01——Front 页码 FI32='1'（非'100'），全表'100'/'200'=0；数据区计数与 6855c97 输出完全一致（GL +528~+660、ML +283~+1372 vs buggy）；`go test ./...` 全绿。已提交 446be5c（未 push，origin 在 1359f99，领先 1 提交）。
- **教训**：excelize GetRows 返回**格式化值**（如"13,500.00"），yuanStrToCents 会去千分位（ReplaceAll ","）；判断"是不是金额"要看**单元格类型**而非"字符串长得像数字"。备份 tag `abandoned-8af3cf0-6855c97` 保留废弃提交。

## 逻辑页码"查看版就不对"的根因与修复（0d04031）
- **用户指出**：逻辑页码连查看版都不正确 → 真正该改的是查看版生成代码，不是打印变换。
- **真根因**：`appendToMLSheet` 计算 logicalPageNum 时用**裸偏移** `r[BindingLeftCols+2]/r[+3]` 判断过次页，但 ML 的 `BindingLeftCols=1`，`+2/+3` = GetRows 索引 r[3]/r[4] = **日/凭证号列**；而"过次页"标签实际在**摘要列** `r[BindingLeftCols+mlOffSummary]=r[1+4]=r[5]`、借方在 `r[+5]=r[6]`。**扫描永远匹配不上 → 每次跨月追加 logicalPageNum 都从 1 重算**，多页科目页码变成 1,2,3,4,2,2。
- **GL 对照**：`getPageNum` 用 `hasPageBreakAt`（BindingLeftCols+4=摘要、+glColBalance=余额），GL 页码一直正确（1..6）——ML 是抄错偏移。
- **修复**：改用已有辅助函数 `mlHasPageBreakAt`（摘要列）+ `!mlIsStructuralBreak`（余额列非空）判断真实过次页，与 GL 对齐。删裸偏移。
- **验证**：按 `scripts/test-e2e.sh` 全量重生成 9 个月（init 2025-10 → 10~12月 → year-close → 2026-01~06）：ML 公益支出页码 **1,2,3,4,5,6**（原 1,2,3,4,2,2）、管理费用 1..5、其余各 1 或 1,2，全部连续；GL 1..6 不变；打印版无 "100/200"；全测试绿。
- **教训**：列索引判断一律用 mlOff* 常量/辅助函数，禁止裸 `BindingLeftCols+N` 手写（GL BindingLeftCols=2、ML=1，偏移不同）。全量验证用 `scripts/test-e2e.sh`（会 open 预览），单月用 init+generate。
