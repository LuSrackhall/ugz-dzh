  1. **同一语义"期初"被存两份**：意图在 `自动识别科目[].期初调整额`/`手动调整科目[].期初调整额`，落地在 `科目树.首次记录.金额`+`余额`回填——代码只读后者，前者死字段 → 手改调整额不生效，git 记录与实际账本对不上（对 git 管理宗旨伤害最大）。
  2. **FirstRecord.Amount 语义过载**：自动识别=首月净额、手动调整=调整额，消费方（GetInitBalanceForGenerate/ensureBackfillForAll）分不清 → M1/M2 病根。
- **修复蓝图（让手改与 add-manual 等价）**：① 让 AutoItems/ManualItems 的 Adjustment 被 GetInitBalanceForGenerate 真正读取（README 承诺的语义）；② 自动识别科目 FirstRecord.Amount 恒置 0（首月净额不再写入，M2 根除）；③ 仅手动调整科目允许回填；④ add-manual 退化为"写配置+校验"的便捷命令；⑤ 属性不按净额推断（M1）。
- 用户宗旨确认：json+凭证.md → 账本；JSON 唯一权威源；git 管变更（新增科目/期初调整/余额回写）。期初修复方向=让 JSON 里的"期初调整额"真实生效，使 git diff 可信。
