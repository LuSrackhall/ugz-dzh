## 跨平台打印版渲染差异：最终方案落地（凌晨 01:30 续昨日排查）

- **需求定论（用户明确）**：最终用户 Mac/Windows 都有，需要"**每端各自正确**"（本端生成→本端打印/PDF 输出正确），**不需要跨端像素级一致**。否决：PDF 跨端分发（用户本地生成）、Windows 缩放补偿（长宽比不一致）、双端统一字体（同字体下预览/PDF 也不一致）。
- **Windows 输出实测（2026-06.pdf，GL 库存现金，Windows WPS 导出）**：表格 **19.49×14.65cm** vs Mac 基准 22.28×16.42cm（宽 -12.5%、高 -10.8%）；数据行行距 **17.8pt** vs 设计 18.5pt（25pt×74%，-6%）；纸张 B5 横向一致；装订边基本一致。→ Windows 渲染整体偏小。
- **实现（已编译+测试通过，Mac 无回归）**：
  - 新增 `generator/platform_compensate.go`：`platformCompensate()` 按 `runtime.GOOS=="windows"` 返回 (colScale=1.143, rowScale=1.04)，Mac=1。
  - `print_common.go transformSheet` 4 处：金额列 sub、拆分非金额列 subW、非金额列 w 均 ×colScale（零宽列保持 0）；行高回填 ×rowScale。
  - 原理：transformSheet 是 GL/ML 打印版列宽/行高的唯一入口，补偿集中在此，查看版与 Mac 端不受影响。
- **待办**：Windows 上重新 build + generate → 导出 PDF → 迭代收敛 colScale/rowScale。
- 教训：excelize v2.10.1 无 PDF 导出；LibreOffice 未装；WPS 无 CLI；PDF 生成靠各端 WPS"打印为 PDF"。PDF 测量用 pypdf 解析内容流矢量坐标（pypdf 的 get_contents() 对 Contents 数组返回空，需直接读 page['/Contents'] 遍历流）。
