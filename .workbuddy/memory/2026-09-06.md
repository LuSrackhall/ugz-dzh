## 下游 0.9.0 bug 反馈修复：期初双源冲突采信 JSON（下午续记）

### 情报（下游用户 agent 会话回传）
- 科目被凭证冲平（期末=0）后静置一个月再重现，期初被错误重置为建账期初——宏远公司1 六月冲平、八月重现期初又变回 1,003 万；下游已手工重建 2025 年余额链 179 处，并称"今后 -f 重跑历史月会复发"（修复思路其侧已存档，未随情报传来）。

### 定位过程（先纯推演后实证）
- 静态推演 0.9.0 干净链路各路径（GetInitBalanceForGenerate 路径 3 含 0——H1 已修、回写循环 1 无条件写 Final=0、-f 级联删、ExtractLastMonthFinals 回退取最后带符号余额行）全部自洽。
- **干净账本 e2e 复现失败**（建账期初→静置 M4 链→冲平→静置→重现→各级 -f 重跑全对）——证明触发态不在正常管线。
- 关键线索 reinterpretation："179 处修复"只修了 **JSON 链**，xlsx 链未动 → 构造双源分歧状态（xlsx 陈旧 + JSON 手修）→ **复现成功**（8 月期末 10,030,500 = 错误期初 1,003 万 + 500）。

### 根因
- GetInitBalanceForGenerate 路径 2（上月 xlsx 账页链）压过路径 3（JSON 权威链）。触发三件套：① 冲平凭证从未级联重建进 xlsx（账页最后期末余额停在冲平前）；② JSON 被手工修正为真值；③ -f 重跑 → 从陈旧账页链读回旧余额 → 循环 1/2 重新污染 Balances（"复发"）。违反铁律三（JSON 是余额唯一权威源）。

### 修复
- 双源比对：健康账本两源恒等（JSON 回写与账页月结同源同月），不一致 → **采信 JSON + 告警**（"⚠ 科目 X 期初双源冲突：账本页链期末 A 元，JSON 权威链 B 月期末 C 元——已按铁律三采信 JSON；…请核对后从冲突月 -f 重建"），-f 重建自愈而非复发。仅单源存在时行为不变。签名 `int64` → `(int64, string warn)`，generate.go 收集打印；双源冲突语义见 balance.go 函数注释。
- 回归：test/e2e/flush_flat_repro_test.go（干净链路 TestFlushFlatSubjectOpeningChain + 双源分歧 TestStaleWorkbookJSONAuthority）+ 单测 TestGetInitBalanceDualSourceConflict。

### 验证（AGENTS.md 1.5 四步全过）
- go test ./... 全绿；bash scripts/test-e2e.sh 全流程（init→2025-10~12→year-close→2026-01~06）通过。

## 新增「科目余额表」sheet（晚间续记）

- **需求来源**：下游回传旧财务软件导出的《4月余额表》（OCR md，11 页，红旗路办事处 2025-04）——七列一体排版（科目编码|名称|方向|期初|借|贷|期末+分段小计+合计）。我们原产出把四个数分散在 {月}期初/{月}期末/科目汇总表 三张 sheet，无一体表。
- **实现**（680eccf）：generator/report_sheets.go `writeSubjectBalanceSheet` 挂进报表套件；科目|方向|期初|借|贷|期末 六列。行=树键节点子树汇总 + **一级科目自动补行**（真实迁移账套树里只定义叶子全路径，一级科目不是树键——首版漏了这层，靠真实 e2e 数据暴露）；全 0 不显示；余额按属性归一（贷科目贷余为正，反向余额显负）；合计按 activity 键（实际记账科目）求和防父子双算。
- **坑×2**：① 补一级行的 generals 块插在 keys 构建之后 → 键集永远缺一级科目（单测抓出，挪到 keys 前）；② 合成汇总行非树键取不到属性 → 方向为空、归一失效，改为继承子树内第一个已定义属性的后代。
- **行为变更**：balance.xlsx 内 sheet 改名「科目发生额汇总」（当月发生额净额口径），让出标准名避免同名不同物（README/技能双目录已同步）。真实账套验证：应收款净贷余 150 万/应付款净借余 37.5 万以负数显形（反向余额），期初表有符号和 ↔ 新表一级行全量对账吻合。
- **未做**（待需求）：科目编码列（编码主键化延后）、分类小计行（损益小计等）、独立导出文件。
