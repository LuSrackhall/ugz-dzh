## "选择性识别三层"澄清（用户问）

- 关键澄清：系统**从不解析明细段内部**——splitPath 只切一刀（首个 '-' 分总账/明细），明细段整段是一个名字。"公益事业-卫生"与"办公费"在系统眼里无结构差异。
- 因此"选择性识别"**不需要任何配置**：想给哪个科目分层=凭证里写带连字符的长明细名；想两级=写短名。选择权在凭证文本，不在配置。
- "总分类账视 N 级为整体两级"→天然如此；"公益支出-公益事业再识别一级"→科目余额表**前缀子树聚合**统一生效（上级行=自身+K-后代）。唯一前提：想让中间层（如"公益支出-公益事业"）在余额表显行 → 树里登记该 key（空节点即可），否则只有一级汇总行自动补。
- 使用纪律：同一总账下别混两层/三层写法——GL/JSON/聚合数学上仍正确（聚合=自身+后代），但 ML 明细列会出现"公益事业"与"公益事业-卫生"伪并列，加总视觉误导。
