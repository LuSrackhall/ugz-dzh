## 澄清：跨年"强制清零"的真实机制 + e2e 脚本测试缺口（用户问出）

- **用户疑问**：26 年账本为何还有管理费用等期初？"不是有强制清零的跨年结转嘛"。真相：**year-close 从不清零**——只告警（损益年末余额≠0 → "疑似漏结转"）+ 出结转草稿 + 复制新年 JSON（余额历史保留）；**清零 = gen-close 凭证**（写入 {year}/closing/，取当年最后余额月、按月末最后一天开凭证、自动登记"本年收益"）+ generate -f 该月并入。F1 设计：告警不阻断，结转是用户主动动作。
- **e2e 演示账套 26 年损益期初非零的原因**：脚本只跑 year-close（:176）从不跑 gen-close → 2025-12 损益期末经 JSON 链变 2026-01 期初（21 个叶子精确相等实证）。**测试缺口**：完整年末流程（gen-close→-f 12月→year-close→重出新年）从未被脚本覆盖——已手动全流程演示验证：gen-close 21 科目 545 万 → 12 月归零 → year-close 零警告 → 2026-01 损益期初 27 个全 0、本年收益期初=-263 万（2025 净收益贷余入权益）。建议：e2e 脚本补 gen-close 环节（待用户点头）。
- 边界：401 生产成本（资产类）年末有意不清零（官方口径）；未分类损益告警不结转。

## 会计准则复核：year-close/gen-close 发现二段结转缺口（用户问出，未修待拍板）

- **用户问**：year-close 合理吗？符合会计准则吗？逐条对照财会〔2023〕14号后结论：**骨架合理（凭证四要素/新账新页/JSON 权威链/告警不阻断/先定义后生成全对），但有一个实质缺口——二段结转缺失**。
- **制度要求年末三段**：①收入/费用→本年收益（gen-close 已做，方向/金额/日期全对）；②**本年收益→收益分配——未分配收益（净亏损相反）——未实现**（322 收益分配在官方表有定义，全仓库零处理）；③分配时各项分配与未分配收益互转（属次年分配方案动作，可不做）。
- **当前后果**：上年净收益以"本年收益"期初带入新年（演示账套 -263 万贷余），次年 gen-close 后两年净收益在同一科目混合，"本年收益"失去年度语义。
- **复核诚实记录**：此前三重复核是"实现 vs 设计稿"+"科目表/方向 vs 官方原文"，年末结转条款从未逐条对照——缺口由用户提问暴露，非审计发现。
- **待拍板方案**：gen-close 增加第二段凭证（本年收益→收益分配，亏损相反，同批写入 closing/）；涉及账务结果变化 + 资产负债表权益列展示调整（收益分配 替代 本年收益）+ 收益分配科目登记路径。
