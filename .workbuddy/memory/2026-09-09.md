## v0.9.9：明细列净额按科目方向定向——红字语义修正（用户发起严肃审计）

- **用户问**：ML 明细列什么时候用红字？跟科目方向有关吗？还是只要贷就一定是负？
- **审计结论**：明细列口径原为统一"净额=借−贷"，与科目方向无关；打印版"负数=红字"（H2）组合下——借方科目碰巧全对（贷冲减→红字），**贷方科目（收入/负债/权益类）整列颠倒**（正常贷发生→红字、冲减/红字冲销→蓝字）。红字凭证（带符号借贷，H2 四格式）在贷方科目同样颠倒。
- **手工账规范**：多栏账分析栏以科目基准方向为正，反向发生额红笔（无负号）。打印版"负数=红字"机制本身正确，缺的是净额未按方向定向。
- **修复**：detailColNet(general, debit, credit)——detailCreditBased(general)（树叶子属性优先/官方推断兜底，sync.Once 缓存）为贷则取负。应用点全链：分录行、writeMLPageBreakRow/writeMLCarryForwardRow（签名+general）、writeMLClosingRow（签名+general）、lastBreakDetailTotals（读显示值须**逆向还原**原始口径防二次翻转）。qt/ytd 的 prev 净额已是原始口径塞 debit/credit 分开 ✓。
- **自查坑 1**：0 期初分支改造时 row 赋值挪进 if → 零值行号分录丢失（同昨天 v0.9.8 的坑——**条件化写行时 row 推进必须留在 if 外**）。
- **自查坑 2**：测试期望把"累计净额"当"单笔净额"算（明细列每行=该笔净额）。
- 演示账套公益支出为借方 → 行为不变零回归（e2e 5.5 PASS）。文档：workflows.md 新增"金额分析列的符号与红字规则"节 + commands.md 产物行，双目录同步；CHANGELOG v0.9.9（贷方向科目符号翻转+零迁移+铁律一说明）；SKILL bump 0.9.9。
