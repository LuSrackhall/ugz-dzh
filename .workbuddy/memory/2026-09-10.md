## v0.10.1：ML 打印分页修复——末页正面缺失（用户问询驱动的覆盖完整性审计）

- 用户问"PDF 打印版中多科目明细账排版分页是否有问题" → 建立**程序化审计方法**：解析 xlsx XML 的 _xlnm.Print_Area 原始区域串 + 扫描 sheet 全部非空格 → 校验三项（未覆盖格/区域重叠/区域数奇偶）。**判定标准：内容必须被区域完整覆盖（漏 = 打印丢内容）**。
- 审计结果：21 张 ML/分离页**全部**有问题（101-197 未覆盖格/页，首个即"明 细 帐"标题在末块右半）→ 真缺陷。
- 根因：mlAreaPlan 按"滑动窗口"模型（末块只取左半，注释假设"末块右侧为空"）——**实测末块右半 = 末页正面**（标题/页码"分第1页(右)"/会计科目/表头区全在）→ **ML 物理结构是"块=页"**（右半正面+左半反面同页码，writeMLPageHeader 两侧同页号实锤），旧假设错误。
- 修复：序列改 [占位正, 页k正(右半), 页k反(左半), …]（正先，对齐 GL）；尾部补空白保偶数（跨 sheet 配对，对齐 glAreaPlan）；**补页矩形取 blocks*blockRows 之后的空行区**——首版放在末块装订列与末块正面区域重叠（校验抓到 1 对重叠 → 挪位）。
- 终态：110 张账页三项校验全归零；全量测试 + e2e 脚本绿。教训：**"实测验证过"的注释可能是局部的**（原注释称 Sliding window 已实测，实际只验证了页数配对未验证内容覆盖）。
- 状态：CHANGELOG v0.10.1 + SKILL bump 0.10.1，commit 本地，发版待批准。

## PDF 验证（用户："你生成个PDF我看看"）——渲染对比方法论 + 环境事实

- **环境事实**：本机无 LibreOffice/Excel；WPS 无 AppleScript sdef、无 CLI；osascript System Events 被沙箱拦 → **无法程序化用 WPS 导出真实 PDF**。可用路径：reportlab 逐区域重绘（本机 venv 已装 reportlab/pypdf）。
- **沉淀工具 `scripts/render-print-areas-pdf.py`**：读打印版 xlsx 的 _xlnm.Print_Area → 逐区域渲染一页 PDF（行列表形式）→ 同时用**旧 mlAreaPlan 算法**重算对比；新版对"旧缺区域"打 ★ 标注，旧版末尾附缺失清单页。用法：`python3 scripts/render-print-areas-pdf.py <打印版xlsx> <sheet名> <输出目录>`。
- 关键坑：**blocks 不能从 openpyxl max_row 推**（含尾部样式行，≠ 生成期 GetRows lastRow）→ 从新区域数反推 blocks（新算法区域数 = 2×blocks）。
- 实证结论（多科目明细账-公益支出，7 块）：修复前 12 页（末页正面 CE181:GC210 缺失）vs 修复后 14 页（★ 新增末页正面 + 补空白页）；新增页内容 = 标题"明 细 帐"、分第 6 页(右)、会计科目=公益支出、明细列名（补助费用/优抚慰问/公共基础设施维护提升/救助补助/集体福利）、明细金额拆位数据——**旧版导出 PDF 会整页丢失**。
