## 语音记账 + MCP 接入方案讨论（结论：方案甲定稿，未立项）

承接 2026-09-04 的"编码 vs 语音"辩论（设计稿 §四已把"语音输入立项工作项"挂触发器）。本轮用户主动重提，并给出完整构想：**MCP 连接器 + LLM agent + 语音/移动端**，用户通过与 agent 交流来记账，取代"给科目编码简化手工录凭证"。用户要求评估，并强调"必须严格限制每次改的不会影响其它已经落地的凭证"。

### 讨论过程（五轮，含两次用户纠正）

**第 1 轮 — 我的初版评估（部分跑偏）**
认可三点：①编码对输入准确性贡献=0（9-04 已定论，编码服务的是"标识稳定性"）；②"凭证就是 md"是方案成立的地基——幂等保护 / `lock` / 先定义后生成 / 借贷平衡 / git 管 JSON 等闸门已就位；③语音是**输入通道选型**，设计稿 §四原文已采纳"agent 对话界面即输入通道"。
但我把"更正场景"的准则（红字冲销）硬套到了"首次录入"上，建议"AI 不能 edit/delete 已提交凭证，要改就开冲销凭证"。

**第 2 轮 — 用户纠正 #1：场景错配**
> "你说的凭证是已经结转月份的凭证。我说的凭证，是还不存在账本、还没有被 CLI 使用过的，就是需要记录的呀！冲销当然是准则，但新录入凭证的场景，我认为我的叙述无可厚非。"

**承认跑偏，重新分两档**：
- **A 档草稿期**：md 还没被 CLI 消费 → 改/删/重说，成本≈0。用户"再对话一次就改对了"在此档**完全正确且最优**。
- **B 档生效期**：已被 generate 吃进当月账本 → 才需要冲销。
- 边界不是"文件落盘"，是"**generate 跑过了**"。

此轮我还提出"草稿区"建议，并查出两个真代码事实：
- `CollectEntries`（`cmd/common.go:34`）与 `ParseDir`（`voucher/parser.go:289`）都是 `filepath.WalkDir` = **递归**。所以 `vouchers/2025_10/_draft/*.md` 会被 generate **静默吃进账本**。
- 重号检测用 `filepath.Glob(voucherDir/*.md)`（`cmd/generate.go:85`）= **非递归且只看文件名**，与解析口径不一致。

**第 3 轮 — 用户选定方案甲 + 纠正 #2**
> "方案甲, md 和每次会话更改或增加的 md 与其对应的 git 的 commit 本身就是草稿。这样我录入这个月 5 号凭证时，就不会影响到前 4 号了，想知道是否影响了，git 历史一看便知，没有任何认知核算成本。"

我提了三条补充，用户逐条驳回/修正：

**第 4 轮 — 用户驳回我的三条**
1. 我说"git 覆盖凭证层、不覆盖账本层"是缺口 → **用户否掉**："我们本身就不覆盖账本层，只要凭证没问题以及 json 文件没问题，账本层是 cli 代码逻辑保证的，与 git 仓库历史无关。" → **用户表述正确**（铁律三：JSON 权威、xlsx 幂等重建）。唯一限定词：生成读上月 xlsx 当期初，故输入是"凭证+JSON+上月账本"；但无上月可纯 JSON 重建、双源冲突采信 JSON，权威链始终在 JSON。
2. 我说"录入必须时序"是前置条件 → **用户改为机器检查**："通过脚本来扫就行了，只要每个月连续没重复没断码就好了…… 不符合就反馈给 agent，让 agent 告知用户，用户决策。" → 更优：是检查不是约束。
3. 我担心 A→B 静默窗口 → **用户否掉**："什么时候要一张凭证生成一次账本了？账本到 8 月，我录 9 月凭证是不影响的呀！而且等我录完凭证，我会自己提示 agent 生成账本呀，**不允许 agent 私自不经过用户同意生成账本**。对于已经生成过账本的月份的凭证，原则上只允许冲销，重复用户再三确认通过 -f 并更改凭证（而且这个不需要担心呀！只要改了，git 历史就有，用户随时可以冲销改回来重新决定）。"

**第 5 轮 — 确认 + MCP vs skill 定位**
用户要求再确认方案，并判断"MCP 更合适"。我同意，并说清理由：skill 的前提是"agent 在账套那台机器上、能读文档敲命令"，语音/移动端 agent 摸不到磁盘 → 该模式失效；MCP 把能力变成可远程调用的语义化工具，**CLI 不消失**、是 MCP server 的实现底座。

**第 6 轮（本轮）— 用户拍板"就用这版" + 网络口径**

### 定稿结论（方案甲）

| 层 | 内容 |
|---|---|
| 输入 | 凭证 md（**md 即草稿**，无草稿区）+ `{year}.json` |
| 权威 | JSON 是余额唯一权威源（铁律三） |
| 保证 | 账本正确性由 CLI 代码保证，**不占 git** |
| 追溯 | git 管凭证 md + JSON；账本层不入 git |
| 时序 | 机器扫（重号 + **断码**），异常 → agent → 用户决策 |
| A→B | 用户显式要求生成 |
| 接入 | MCP（局域网优先），CLI 为实现底座 |

### 新增代码事实核查（本轮 grep 确认）

- **断码检查完全不存在**：`grep 断码|连续性|缺号|gap` 在 `cmd/` `voucher/` 零命中；现有只有**重号告警、不阻断**。
- **`voucherNumRe = 记字第\D*0*([0-9]{1,6})`**（`cmd/generate.go:386`）要求文件名含"记字第"，而 `CollectEntries` 递归扫所有 `.md` 与该格式无关：

| 月目录文件 | 记进账本 | 告警 |
|---|---|---|
| `记字第0026号.md` | 会 | — |
| `记字第0026号 副本.md` | 会 | 重号（不阻断）|
| `草稿.md` / `模板.md` / `2026-03-05.md` | **会** | **完全静默** |

- **CLI 无任何创建凭证的命令**：`cmd/` 全量为 init / add-manual / map / subjects / subjects-scan / opening / generate / check / lock / gen-close / year-close / doctor / config / reset / install-skill —— **全是读凭证，凭证只由人或 OCR 产生**。这是语音/MCP 方案唯一的最小代码缺口。
- **依赖现状**：`go.mod` 仅有 cobra/excelize + x/crypto、x/net、x/text（均 indirect），MCP 接入需决定用官方 Go SDK（新直接依赖）还是手写 Streamable HTTP JSON-RPC。

### 红线（写入 MEMORY.md）

1. generate 不进 MCP 工具面（"不允许 agent 私自生成账本"只有不暴露才是结构性保证）。
2. 月目录白名单：只准 `记字第XXXX号.md`。
3. MCP 实例绑定单一账套根目录，路径不接受 LLM 传参。
4. 硬规则只在 CLI，禁止上移到 MCP 层。
5. 未配 token 时禁止非本机绑定（fail-closed）。

### 网络口径（用户拍板，本轮）

**局域网优先**——"只要在一个局域网，我就能接上这个 mcp"。这正好是"数据不出本地"商业前提（2026-08-28 定的 ugz-dzh 标的）最干净的实现形态：数据连局域网都不出。外网中继（server 主动外连中继、不开入站端口、中继只承载对话文本）**延后**，同一 server 加传输层即可，不需要重构。
