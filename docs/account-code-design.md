> "做到接近 100% 很简单：给出可视化的展示，发现凭证有出入即时告知 agent；收紧后的策略，新增科目需确认，再加上 git 保底——足够了。"

## 一、问题清单（三轮评审核实的代码事实）

1. **内置 17 类科目表残缺**：`balance/balance.go:710` `accountTypes` 仅 17 个一级科目。e2e 实证 `专项应付款-日间照料中心` → `未分类`（官方 241 缺失）。累计折旧/在建工程/库存物资/短期借款/一事一议资金等全部缺失。
2. **名称 key 三层精确匹配零容错**：md 单元格原文（仅 TrimSpace，`parser.go:96,109`）→ `map` 精确匹配（`cmd/common.go:62-88`）→ `accountTypes` 精确匹配（`balance.go:599-602`）。错名（OCR/语音同音字，如"管埋费用"）无任何模糊匹配，静默入树（`balance.go:287-317`）。
3. **两处真静默（本期必须堵上）**：
   - 收支结余表对未分类科目直接 `return`（`generator/report_sheets.go:204-207`）——无痕丢行；对比资产负债表尚有表底单列（`report_sheets.go:168-178`）。
   - 年末损益结转静默跳过未分类科目（`cmd/gen_close.go:96-98`），year_close 告警只覆盖已知收入/费用（`cmd/year_close.go:66-70`）——未分类损益不结转、不告警、跨年带入新账。
4. **双回退不一致**：`inferPropertyByType`（balance.go:533）未知→"未分类"；`classifyAccount`（balance.go:690）未知→"费用"。同一科目两条路径身份不同。
5. **科目树无删除/合并机制**：错名节点永久留存、随 year-close 带入新年；`map` 只加解析期映射（`cmd/map.go:56-60`）。

> 语音方案的正确角色是**输入通道选型**（采纳：agent 对话界面即输入通道，无需新建局域网语音模块）；它不构成"科目标识不需要稳定"的反证。编码所服务的标识层问题（改名→树 key 变化→`科目顺序`/`合并总账科目`/`总分类账忽略科目`名单静默失效、跨年无纽带、手工界面 value/label 分离）全部挂触发器延后。

## 二、本期范围（一期发版，5 件事）

### 2.1 官方 42 科目常量表（地基，零 schema 变更）

- **按最终结构定义**（唯一留口子，避免将来主键化重塑表）：

```
编号（官方顺序号）| 编码 | 名称 | 属性(借/贷) | 官方大类 | 损益段位(收入/支出/空) | 现行类别(资产/负债/权益/收入/费用)
```

- **运行时只消费"现行类别"**：`AccountTypeOf` 签名与返回值集合**冻结为现行五类**（资产/负债/权益/收入/费用）——`report_sheets.go:114-141` 的 switch 只认这五个字符串，新增"成本/损益"类别会落入 case 空档 → 既不进左右列也不进未分类区，静默消失。官方大类/段位/编码仅作常量表数据字段，供延后项消费。
- **401 生产(劳务)成本 显式决策**：现行类别 = **资产**。理由：年末余额经济实质是在产品，应进资产负债表左列且不被年末清零；映射"费用"会被 gen-close 清零；留空则资产负债表漏项。常量表备注写明，P4 校正时改挂"成本"。
- **零迁移**：补全后按名归类自动正确，旧账套无需任何 JSON 迁移；已存在的"未分类"节点保持原状，由确认流程/subjects import 修正。
- **排序不动**：账页排序行为保持现状（科目顺序配置 > 现状字典序）。改默认排序会改变既有账本页序，延后。

### 2.2 堵两处真静默（小改动高价值，"延后严格收紧"……不对，是收紧生效的前提）

- **收支结余表**：未分类科目改为单列显示（"未分类科目（类别未知，不计入合计）"段，对齐资产负债表现状做法），不进收入/费用合计。
- **gen_close / year-close**：对"类别未知且余额≠0"的科目显式告警（清单：科目名/余额），不改变结转行为本身（仍不结转未分类科目），但让 agent 每年结转时必然看见。

### 2.3 `subjects scan`（凭证 → 候选审核表）

```
ledger subjects scan -v <凭证目录> [-o 候选.csv]
```

- **宽容解析**：只提取（总账,明细）对 + 出现频率，**不要求**凭证号可解析/借贷平衡/同年同月——必须能吃下原始 OCR md（否则重蹈 output-harvest 被 generate 级阻断卡住的覆辙）。
- **权威基底原则（评审最重要的修正，不得被"扫凭证出表"覆盖）**：迁移审核表的基底 = **旧账期末科目余额表逐行转录**（migration-design.md 原则），scan 产物仅**并入做双向 diff**：
  - 余额表有而凭证无 → 正常存量科目（固定资产/累计折旧/资本/公积公益金等期初最重科目往往在凭证里一次不出现，scan 看不见它们）；
  - 凭证有而余额表无 → 本期新发生科目或 OCR 错名 → 需确认或 `map` 归并。
- 输出候选 CSV：`科目,方向(官方表建议),期初余额(旧账转录值),备注,出现频率`。**不含编码列**（将来加列零成本）。
- 试算平衡闸门（`opening import`）与验收闸门（`check --vs` + 资产负债表三数对平 → `lock`）沿用 v0.8.0/migration-design 既有机制。

### 2.4 generate 收紧（行为变更，用户拍板纳入本期）

- 生成前：凭证科目（经 `map` 归并后）逐一对照科目树。
- 未定义科目 → 输出清单（名称/出现笔数/样例凭证文件）→ **默认中止**，并给出指引：`subjects scan` / 旧账 diff → 确认 → `subjects import` → 重跑。
- `--allow-new` 显式逃生：自动登记（`方式=自动识别`，属性=名称匹配官方表或未分类），兼容旧行为与临时场景。
- 交互终端可后续加 Y/n 询问分支；agent 场景以"中止 + 清单 + 指引"为主路径（agent 拿到清单直接转成确认对话）。
- **openspec/project.md 铁律 3 同步修订**："科目自动管理" → "先定义后生成；`--allow-new` 为显式逃生"。

### 2.5 check 可观测化

- `check` 输出统计行："未分类科目 N 个（余额合计 X 元）" + 逐科目清单。
- 事故定义可观测化：未分类余额>0 连续 3 个月未处理、或跨年带入新账 → 立即处置。
- `subjects remove/merge`（错名节点并入正确科目）入 backlog——现状科目树无删除机制，这是收紧后处置污染的配套原语。

## 三、目标工作流

### 3.1 迁移 SOP（村委会旧账迁入）

```
① init 建账
② 旧账期末科目余额表逐行转录 → 审核表基底（权威：科目清单与金额一律来自旧账）
③ ledger subjects scan -v <凭证目录> → 候选表 → 并入双向 diff
④ agent 逐行确认/补方向（低置信处追问老板）→ 定稿审核表
⑤ ledger subjects import -f 审核表.csv      （登记科目+属性）
⑥ ledger opening import -f 审核表.csv       （期初+试算平衡强制闸门）
⑦ ledger check --vs 审核表.csv + 资产负债表三数对平   （验收闸门，兜住"差额倒挤"）
⑧ ledger lock -m <建账月>                    （锁死基线）
⑨ ledger generate                            （收紧生效：凭证科目 ⊆ 已定义科目）
```

### 3.2 日常月度

```
凭证就位 → generate（遇新科目 → 清单中止 → 确认补表 → 重跑）
        → check（未分类统计行）→ lock → git commit（JSON diff = 可视化保底）
```

## 四、延后项与触发器

| 延后项 | 触发条件（任一即立项） |
|---|---|
| **科目编码主键化**（编码落 JSON、map/配置名单换编码引用、跨年纽带） | ① 镇级汇总/多账套或带编码格式的报送需求；② 第一次真实科目改名事故且跨年账已装订；③ 手工录入界面立项；④ 账套 ≥2 个会计年度出现跨年比较/审计追溯同科目需求；⑤ 配置名单第一次因改名静默失效被发现 |
| **报表按官方大类/段位归类**（P4） | 与主键化同触发；届时 AccountTypeOf 返回值集合扩展，report_sheets/gen_close 同步改造 |
| **默认账页排序改官方序** | 用户明确提出；会改变既有账本页序，需明示迁移说明 |
| **语音输入立项工作项** | 语音/口语记账功能立项时：总账列归一化（内部空格/全半角）、模糊匹配与同音字候选提示（"管埋费用"→建议"管理费用"）、复述确认规范。（静默入树通道已被本期收紧封死） |
| **subjects remove/merge** | 首次出现树污染需要清除时（配合收紧） |
| **资产负债表 401 并入"存货"行** | 报表对齐时一并做——官方编制说明：存货项目按"库存物资、生产(劳务)成本等科目余额合计填列"；现行按科目单行列示（401 作资产侧单行），不影响合计正确性 |

## 五、验收标准（修改工作流五步）

1. `go test ./...` 全绿（新增：常量表完整性 42 科目、401 映射、两处堵漏报表行为、收紧清单输出、`--allow-new`）。
2. `bash scripts/test-e2e.sh` 通过；e2e 金标准 diff 中只允许出现**修正性质差异**（此前"未分类"科目开始正确进报表/告警）。
3. 三生成路径（GL / MergeGL / ML）数据不丢、余额链连续。
4. 跨月追加：`bash scripts/test-e2e.sh --skip-test` 多月份生成，期初链与结转正确。
5. 收紧行为回归：旧账套用 `--allow-new` 重建结果与收紧前一致（逃生路径保真）。
