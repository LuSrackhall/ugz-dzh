# 账务数据可靠性与正确性审计报告（2026-08-26）

审计范围：合计/月结行逻辑（GL / 合并 GL / ML）、余额连续性、结转、期初/累计提取、凭证解析、
生成流水线。方法：代码走查 + 全新流程复现（init 2025-10 → 2025-10/11/12 → 年结 → 2026-01）+ 实测数据核对。

---

## 一、严重问题（数据错误，需优先修复）

### H1. 本年累计/本季累计跨年污染（年界 bug）— 已实测复现，**已修复（commit 7f16664）**
- **位置**：`generator/monthly_close.go` `ExtractYtdTotals` / `ExtractQuarterlyTotals`；
  `generator/monthly_close_ml.go` `getDetailPrevYearTotal` / `getDetailPrevQuarterTotal`。
- **根因**：均以 `monthKey < wb.Month` 字符串比较取"截至上月"，**无同年过滤**。年结
  （`cmd/year_close.go`）只建空 xlsx、不清理科目树跨年 Balances（`cp 2025.json 2026.json` 全量保留）。
  于是 2026 年任意月份的本年累计 = 2025 全年发生额 + 2026 累计。
- **实测**（全新流程）：2026-01 银行存款 本年累计 = 13,472,165（2025 全年）+ 114,320（2026-01）
  = **13,586,485**，与 sheet 单元格完全一致；47/47 个科目全部带 2025 余额。ML 同样被污染：
  公益支出 本年累计 1,518,470.14 = 树累计 1,291,524.32 + 当月 226,945.82。
- **修复**：4 处提取统一加 `strings.HasPrefix(monthKey, wb.Month[:5])` 同年过滤；
  `GetInitBalanceForGenerate` 跨年取期末做期初保持不动（期初=上年末是正确语义）。
  修复后验证：2026-01 本年累计 = 本月合计（114,320 / 226,945.82），2026-02 正确累加，
  2025 年内累计不受影响，go test 全绿。

### H2. 无"借贷平衡"校验 — 凭证错误无法提前发现
- `cmd/check.go` 仅校验科目树；`cmd/generate.go` 仅校验同年同月。**全库无"每张凭证借方合计=贷方合计"校验**。
- 凭证解析（`voucher/parser.go`）接受负数（红字），负数直接进入 DebitCents/CreditCents：
  - 本月合计/本年累计会把红字显示为负金额；
  - 借贷不平衡的凭证会静默通过，导致账本失衡而无人报警。
- **修复方向**：generate 前逐张凭证校验 `sum(借方) == sum(贷方)`（绝对值口径）、单侧金额非负、
  精度合法；红字规范化（负数折入对侧或明确负数列示）。

## 二、中等问题（数据完整性/结构风险）

### M1. 科目属性按首月净额推断，会得出错误属性
- `balance/balance.go` `UpdateBalancesAfterGenerate`：新科目 `Property = InferAccountProperty(act.Debit - act.Credit)`。
  实测：**银行存款**（资产，正常应为"借"）2025-10 首月净额为负 → 被标记为"贷"。
- 目前 `Property` 未参与余额/方向计算（余额按"借正贷负"符号约定，方向显示正确），
  但属性本身是错误信息，且 `FirstRecord.Amount = 首月净额` 与"期初调整额"语义混用（见 M2）。
- **修复方向**：属性应来自科目表/用户配置，而非首月净额推断；首月净额不应写入 FirstRecord.Amount。

### M2. 自动识别科目的"幻影期初"（ensureBackfillForAll 误回填）
- `balance/balance.go` `ensureBackfillForAll`：凡 `FirstRecord.Amount != 0` 的科目，把该金额
  回填到 `StartMonth..首次月-1` 的 Balances（期初=期末=该金额）。自动识别科目 Amount=首月净额（常非零），
  会被当作期初调整回填——重跑/补跑账户尚未存在的月份时，期初表凭空出现该科目余额
  （如银行存款被回填 2025-01..09 为贷方 118,119.59）。
- **修复方向**：仅"期初调整（手动）"科目允许回填；自动识别科目 Amount 置 0 或单独标记。

### M3. generate 非幂等 — 同月重跑会重复追加
- 无 `-f` 时重跑同月：分录、月结行全部再追加一遍（无幂等/去重保护），账本数据翻倍。
- **修复方向**：generate 前检测目标月 xlsx 是否已含当月"本月合计"行，存在则告警/要求 `-f`。

### M4. 无活动月份的结构残留（月结行滞留）
- 科目当月无分录 → `changedSheets` 过滤后跳过月结；sheet 为上月拷贝，上月月结行保留在数据中间。
  实测 2025-12 银行存款 sheet 中 r16-18 是 **10 月**的月结行，之后才接 12 月数据与 12 月月结。
  余额连续性正确（12 月末 2,552,667.42 连续 ✓），但账本中间出现非当月的"本月合计"，易混淆。
- **修复方向**：无活动月份至少补"本月合计 0/0 + 期末余额=上期"行，或明确设计为跳过并在文档注明。

## 三、低风险 / 设计取向（建议但不紧急）

- **L1 期末表合计=净额**：`WriteFinalSheet` 合计为全部科目期末净额（平衡账≈"平"0）。
  标准做法宜分列"借方合计 / 贷方合计"（试算平衡口径）。
- **L2 期初/期末表列出零余额科目**：initials 含全部科目树 → 零余额也列"平 0.00"（噪声）。
- **L3 ML 月结行口径混用**：主借/贷列=毛额累计，明细列=净额方向（net=借-贷 折叠单侧）；
  同一行两种口径，需在表样/文档注明，避免阅读误解。
- **L4 红字负数显示**：合计行可能显示负金额，打印口径需确认（负数/红字均合法但需一致）。

## 四、验证为正确的部分（未发现问题）

- **期末余额公式**：借正贷负符号约定下 `期初 + 借 - 贷` 对资产/负债/权益通用 ✓；
  `directionFor` 零余额返回"平" ✓。
- **运行余额逐行计算**：GL `balance + Debit - Credit` + 方向，ML 期末取 sheet 最后运行余额（最稳健）✓；
  跨年结转期初 = 上年 12 月末（ExtractLastMonthFinals 读期末行带符号）✓。
- **合并 GL 聚合**：`isChildOf` 前缀匹配无假阳性，父级=子级合计 ✓。
- **凭证号排序**：int 数值排序 ✓（非字符串词法序）。
- **金额精度**：分整数运算 + `Round(val×100)` ✓。
- **同年同月校验 / 科目树校验** ✓（但见 H2 缺借贷平衡校验）。
