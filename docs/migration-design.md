# 账套迁移设计：科目建立与期初余额导入

> 状态：设计已定，待评审后实施（关联 TODO.md「账套迁移」节）。
> 背景：目标客户（小微企业主 / 代帐会计）带着历史手工账或代帐账接入 ledger。
> 迁移的最大成本不是历史凭证（OCR→md 已有独立项目解决），而是**科目的建立**和**期初余额的导入**。本文档解决这两件事，要求：方便、准确、可靠。

## 一、核心设计原则

1. **科目名可以借历史凭证，金额一律来自旧账余额表。**
   历史凭证（OCR 产物）只用来「盘点科目名」——哪些科目在业务里出现过；所有金额（期初余额）一律以旧账的科目余额表为准。这样 OCR 质量只影响科目名清单的完备度，**不影响任何金额的正确性**——准确性从此不依赖 OCR 质量。
2. **权威科目清单 = 旧账科目余额表 ∪ 临时账本盘点结果，双向 diff 后人工审核。**
   历史凭证自动纳入的科目一定有遗漏，也可能混入 OCR 错名噪声；旧账余额表则天然完整、权威。两者双向比对：
   - 清单有、余额表无 → 疑似 OCR 错名/噪声 → `map` 纠正或从清单剔除；
   - 余额表有、清单无 → 真遗漏（余额表通常只列有余额科目，无余额但会发生的科目靠盘点补充）→ 人工补建。
3. **双闸门验收，缺一不可。**
   - 闸门一（机器）：期初试算平衡（借方合计 = 贷方合计），`ledger check` 强制校验（现状即 error 阻断）；
   - 闸门二（报表级金标准）：新账生成的资产负债表与旧账对应报表「资产合计 / 负债合计 / 权益合计」三数对平，期初余额行与旧账科目余额表逐项核对。
4. **git 纪律贯穿全程，每步一 commit。**
   OCR 原始凭证先原样入库作基线，此后一切修正（map 或改 md）都发生在基线之上，历史可追、篡改可见（规则已固化在 SKILL.md「git 纪律」节）。

## 二、三种迁移模式

| 模式 | 做法 | 适用 | 成本 |
|---|---|---|---|
| ① 当年入账 + 往年期初（**推荐默认**） | 启动月 = 当年 1 月（或当年最早已发生月）；期初 = 上年末科目余额表（代帐年报现成）；当年已发生月份的凭证逐月迁入正式账 | 中途从代帐/手工账接手 | 中 |
| ② 迁移日期初起账 | 启动月 = 迁移次月；期初 = 迁移日科目余额表；历史凭证只用于盘点 | 当年凭证拿不齐 | 低 |
| ③ 全量历史迁移 | 所有年份凭证逐年入账，期初只设最早年初 | 老板要求完整电子历史账页 | 高 |

- 模式 ② 的已知代价：收支结余表的「本年累计」只含启动月之后，与税务申报的年度累计口径不一致，申报时需 agent 用旧账资料补算——所以优先模式 ①。
- 模式 ③ 的科目盘点、期初导入流程与 ①② 完全一致，只是把「逐月生成」扩展到往年。
- 模式 ① 若拿不到上年末余额表：由 agent 从「迁移日余额表 + 盘点账本」**机械化倒推**年初余额——盘点账本的科目树已含各科目当年累计借/贷发生额，年初余额 = 迁移日余额 ∓ 当年净发生额（资产/费用类：年初 = 迁移日余额 − 净借方发生；负债/权益/收入类反向）；旧账资料与倒推值不一致的科目逐项标记人工核对，复核后才准进审核表。仍拿不到迁移日余额表则退回模式 ②。

## 三、目录结构约定（推荐布局）

输出根目录 = git 仓库根（一个老板/公司一个仓库；代帐会计一人多司 → 一司一仓库，或多司多目录一仓库）：

```
<账套仓库>/
├── .gitignore                # 忽略派生产物（见下）
├── README.md                 # init 生成
├── print-config.json         # 打印版配置（init 生成）→ git
├── vouchers/                 # 凭证输入 → git
│   ├── _originals/           # OCR 原始输出，基线提交后不再改动
│   └── YYYY_MM/*.md          # 修正后用于生成的凭证
├── opening/                  # 迁移材料 → git
│   ├── 建账审核表.csv         # 一张表贯穿全程（阶段1定稿 → 阶段2/3 导入输入）：
│   │                         #   列 = 科目 / 方向借或贷 / 期初余额 / 备注
│   └── 旧账资料/              # 旧账报表、余额表原件（jpg/xlsx/pdf 等），agent 转录进审核表
├── output-harvest/           # 临时盘点账本（不进 git，可随时删除重建，与正式 JSON 完全隔离）
└── output/                   # init -o ./output
    └── <年>/
        ├── <年>.json         # 权威源 → git
        └── <年>-MM.xlsx / ledger.* / balance.* / print/ / closing/   # 派生 → 不进 git
```

`.gitignore` 内容（init 暂不生成，建仓时由 agent 创建，R3 待实现）：

```
*.xlsx
ledger.csv
balance.csv
print/
closing/
output-harvest/
```

原则：**输入（凭证、迁移材料、配置、JSON）进 git；生成品不进 git**——随时可由 JSON + 凭证重建，与 README 备份章节一致。

## 四、迁移流程（六阶段，每阶段至少一个 commit）

### 阶段 0：建仓与基线
```bash
git init && 创建 .gitignore
git add . && git commit -m "迁移: 账套建仓"
# OCR 原始凭证原样放入 vouchers/_originals/（此时尚未修正）
git commit -m "迁移: OCR 原始凭证入库（基线，未修正）"
ledger init -s <启动月> -o ./output
git commit -m "迁移: ledger init 建账（启动月 …）"
```

### 阶段 1：科目盘点（harvest）
1. `ledger map` 先纠高频 OCR 错名（从 generate 的自动识别列表与报错中发现可疑名），commit `映射: …`
2. 历史凭证在**临时目录**跑生成：`ledger generate -v vouchers/2025_03 -o ./output-harvest`（逐月或抽样均可）——新科目自动进入 `output-harvest/<年>/<年>.json` 的科目树；正式 JSON 完全不受影响
3. 合并候选清单：临时 json 科目树 ∪ 旧账科目余额表科目，**双向 diff**（规则见「核心设计原则」第 2 条）
4. 产出 `opening/建账审核表.csv`（**一张表贯穿全程**：科目 / 方向借或贷 / 期初余额 / 备注）——方向由盘点账本推断 + 旧账余额表预填，期初余额取自旧账余额表（无余额科目留空），与老板**一次确认全表**，commit `迁移: 建账审核表定稿`

### 阶段 2：科目建立
- **目标命令** `ledger subjects import -f opening/建账审核表.csv -j output/<年>/<年>.json`：按审核表批量登记科目并设置科目属性（借/贷，读「科目/方向」两列，与阶段 3 共用同一张表）——内部调用已有的 `SetAccountProperty`（该函数目前无 CLI 入口）
- **过渡做法（当前版本即可跑通）**：agent 按文档化 schema 直接编辑 JSON——科目树补节点属性，期初≠0 的科目同时在「手动调整科目」建条目；`ledger check` 校验科目树一致性；commit `迁移: 科目建立（N 个）`

### 阶段 3：期初余额导入（核心）
输入 `opening/建账审核表.csv` 中「期初余额」列非空的行（金额来源 = 旧账科目余额表：模式①用上年末；模式②用迁移日）：

```csv
科目,方向,期初余额,备注
银行存款-工商银行,借,152300.00,
库存现金,借,2000.00,
固定资产-电脑设备,借,8000.00,
累计折旧,贷,1200.00,备抵科目
应付款-张三,贷,50000.00,
资本,贷,100000.00,
```

**目标命令** `ledger opening import -f opening/建账审核表.csv -j output/<年>/<年>.json [--dry-run]`，写入时逐项校验，任一失败即拒绝并列出明细（`--dry-run` 只打印将写入的科目/金额与校验结果、不落盘——先 dry-run 迭代到全部通过，再正式导入）：

1. 科目已存在（先阶段 2），且不在 `合并总账科目` 父级中（父级禁止直接设期初）；
2. 科目属性非「未分类」，且属性与 CSV 方向一致（借↔借、贷↔贷）；
3. **试算平衡**：Σ借方金额 = Σ贷方金额，不平拒绝并打印差额——不平衡说明旧账本身有问题，停下来和老板对账，而不是把错误带进新账。

写入语义与 `add-manual` 完全一致（`手动调整科目.期初调整额`，锚定建账月）；符号转换：方向借 → `+金额`，方向贷 → `-金额`（净额口径：借正贷负）。CSV 必须 UTF-8 无 BOM，Excel 导出的 GBK CSV 由 agent 先转码。

**过渡做法（当前版本即可跑通）**：`ledger add-manual` 逐条录入（借方余额传正数、贷方余额传负数），或 agent 直写 JSON；录完必须 `ledger check`（期初不平会以 error 阻断），commit `迁移: 期初余额导入（试算平衡 ✓）`。

### 阶段 4：验收（双闸门）
1. 闸门一：`ledger check` 期初试算平衡通过；加 `--vs opening/建账审核表.csv` 时逐项比对 JSON 期初与老板批准的审核表（防录入漂移，属 R2 范围）；
2. 闸门二：`ledger generate` 启动月（建账月已生成过则 `-f`），打开 xlsx 核对：
   - 期初余额行与旧账科目余额表**逐项**一致；
   - 资产负债表「资产合计 / 负债合计 / 权益合计」与旧账对应报表**三数对平**。
3. 偏差处理：多数是类别错（未分类/方向反）或科目遗漏 → 回阶段 1/2 修正后重建；
4. 通过 → `ledger lock` 锁定建账月 → commit `迁移: 期初导入完成（三数对平 ✓）`。

### 阶段 5：转日常
- 模式①：从当年 1 月起逐月把凭证放入 `vouchers/YYYY_MM/` 并 `generate`（补齐年度累计口径），到迁移月后转入标准月度流程；
- 模式②：直接进入标准月度流程；
- `vouchers/_originals/` 与 `opening/` 永久保留作为源档案。
