## Why

会计软件设计专家（agent-4c298bc4，第五轮）审查结论：系统可靠性出色，但缺"法定最小合规件"。复核确认（含《会计基础工作规范》官方条文与 e2e 真实数据验证）：

1. **日记账缺失**：《规范》第三十四条要求总账/明细账/日记账齐备，现金/银行日记账必须逐日结出余额——目前系统无此账簿；数据已确认覆盖（Entry 含日期/凭证号/摘要/金额，对方科目可推导）。
2. **期初/期末表口径**：当前为净额余额表（合计≈0 无勾稽意义），应为借贷分列试算平衡口径。
3. **year-close 流程断层**：只建空 xlsx、不生成新年度 JSON（须手动 cp）。
4. **损益结转无草稿**：跨年"损益清零"靠手工结转凭证，year-close 已告警但无分录草稿建议。

## What Changes

1. **现金/银行日记账**：新 sheet `现金日记账`（库存现金）+ `银行存款日记账`（银行存款及子科目）——筛选当月分录按日期逐笔排序，列：日期/凭证号/摘要/对方科目/借方/贷方/余额；**每日小计（日结）**、月末本月合计/本年累计/期末结存；余额=期初+逐笔借-贷；现金余额为负 → 提示。
2. **期初/期末表借贷分列**：期初表/期末表改为试算平衡口径——每行按科目属性（资产/费用→借方列，负债/权益/收入→贷方列）列示金额；表尾**借方合计/贷方合计**，不平衡显示差额。
3. **year-close 生成新年度 JSON**：year-close 自动复制 `{year}.json → {year+1}.json`（科目树/配置/余额历史保留，期初锚定语义不变）。
4. **损益结转凭证草稿**：year-close 对损益类（收入/费用）科目列出结转建议分录（借收入贷本年收益等，按期末余额方向）。

## Capabilities

### New Capabilities
- `cash-bank-journal`: 现金/银行日记账（逐日逐笔、日结月结、对方科目）

- `year-close-json`: year-close 自动生成新年度 JSON
- `pnl-close-draft`: 损益结转凭证草稿建议
