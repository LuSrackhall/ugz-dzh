## Why

审计（docs/audit-2026-08-26.md）发现期初处理机制存在系统性缺陷，根源是 JSON 设计中"期初"这一语义被拆到两个存储位置，且代码只认其中一个：

1. **期初调整额是死字段**：`自动识别科目[].期初调整额` / `手动调整科目[].期初调整额` 在生产代码中无任何读取点，`GetInitBalanceForGenerate` 从不读它们。README 宣称"编辑期初调整额即可调整期初"**不生效**——git diff 显示改了期初，账本却无变化，git 记录与账本不一致，直接破坏"JSON 唯一权威源 + git 管变更"的项目宗旨。
2. **首次记录语义过载（M2 幻影期初的病根）**：`科目树.首次记录.金额` 在自动识别科目中存"首月净发生额"、在手动调整科目中存"调整额"。`ensureBackfillForAll` 只看 `FirstRecord.Amount != 0` 就回填，导致自动识别科目的首月净额被误当期初调整回填到未记账月份（实测银行存款 2025-01..09 期初表凭空出现 118,119.59）。
3. **科目属性按首月净额推断（M1）**：银行存款首月净额为负被标成"贷"。属性虽不参与余额计算，但属于错误信息。
4. **期初行摘要不区分来源**：新科目/中途建账的期初行也统一写"上年结转"，会计准则上"建账时点余额"应写"期初余额"。
5. **无期初试算平衡校验**：期初录入错误（借≠贷）无法提前发现。

## What Changes

1. **期初调整额真实生效，且不破坏余额链**（铁律二优先）：
   - `GetInitBalanceForGenerate` 新增来源：**仅当调整额的"生效月/首次月 == 当前月"时**，期初直取调整额（手动调整科目需调整额≠0）；**其余月份一律走上月期末 → 余额历史续链**，保证余额链连续。
   - 跨年安全：自动识别科目的 `首次月份` 是上年，2026 年各月 ≠ 上年首次月，故跨年 2026-01 期初 = 2025-12 期末（prevFinals），调整额不会覆盖上年末——与审计 H1"跨年取期末做期初"的语义一致。
   - 中途补记（生效月早于当前月）：历史 xlsx 不可改（铁律一），规定工作流为**用 `-f` 自生效月起级联重建**，重建时生效月==当前月命中调整额。
2. **自动识别科目不再写首月净额**：`UpdateBalancesAfterGenerate` 新科目 `FirstRecord.Amount` 恒置 0；首月净额不再进入期初链路（M2 根除）。
3. **仅手动调整科目允许回填**：`ensureBackfillForAll` 只对 `手动调整科目`（调整额≠0）回填 `启动月..生效月-1`，自动识别科目不再回填。
4. **旧数据迁移（自愈）**：新增 `PurgePhantomInitials(cfg)`，generate 加载 JSON 后自动执行——对 `首次记录.方式=="自动识别"` 的科目：`首次记录.金额` 置 0、删除余额历史中 `月份<首次月` 且 `借方==0 && 贷方==0` 的幻影记录（只可能是回填产生）。幂等，重跑即清理历史幻影期初。
5. **科目属性按类别推断**：资产/费用 → 借，负债/权益/收入 → 贷（替代按首月净额推断）；未知类别默认"借"，`check` 对未知类别科目提示可 `SetAccountProperty` 修正。
6. **期初行摘要按来源区分 + 补中途建账期初行**：
   - 生成期初映射时同步记录来源（`initialSource[account]`）：调整额生效 → `adjustment`，其余 → `carryover`。
   - 摘要规则：来源为 `adjustment` → **"期初余额"**；否则当月为 1 月 → **"上年结转"**；其余 → "期初余额"。
   - 触发条件扩展：已有 Sheet 且期初≠0 且（当月为 1 月 **或** 当月有调整额生效）→ 插入期初行（原实现限 `-01`，中途补记不插行，本次补上）。
7. **期初试算平衡校验**：`check` 命令校验全部科目**最新月份快照**的期初 借合计=贷合计（不平报错）；`generate` 对当月期初映射校验（不平告警不阻断，避免历史数据卡死）。
8. **-f 级联重建基线正确**（中途补记工作流 D3 的前提，实测发现）：`-f` 由"删除晚于当月的 xlsx"改为"删除当月及以后"；`NewWorkbook` 复制上月时增加跨年判断（不同年度不复制、新建空工作薄）——确保 `-f` 重建时期初取自正确的上月期末/JSON，不被旧版当月文件污染。

## Capabilities

### New Capabilities
- `initial-balance`: 期初机制规范——期初调整额来源优先级（生效月==当前月直取、其余续链）、回填规则、幻影期初迁移、科目属性规则、期初行摘要规则、期初试算平衡校验

### Modified Capabilities
- `cli-commands`: `check` 命令新增期初试算平衡校验与未知类别提示；`add-manual` 语义保持（仍为写入手动调整科目的入口），行为对齐新期初链路
- `excel-generation`: 期初行摘要按来源区分（上年结转 / 期初余额），并补中途建账期初行触发

## Impact

- `balance/balance.go`: `GetInitBalanceForGenerate`（调整额来源+生效月语义）、`UpdateBalancesAfterGenerate`（FirstRecord.Amount 置 0、属性按类别）、`ensureBackfillForAll`（仅手动回填）、新增 `PurgePhantomInitials`、新增期初平衡校验函数、类别推断函数
- `balance/balance_test.go`: 同步更新断言 + 新增迁移/优先级/校验测试
- `generator/gl_sheet.go`: `insertCarryForward` / `insertCarryForwardAtRow` 增加来源摘要参数、触发条件扩展
- `generator/generate.go`: 期初来源记录、幻影迁移调用、期初映射校验（告警）、`appendCarryForwardOnly` 摘要
- `cmd/check.go`: 期初试算平衡校验、未知类别提示
- `README.md`: 修正期初调整说明（与实现一致，含 -f 级联重建工作流）
- 不变：生成流程骨架、余额公式、跨年结转逻辑（year-close 本身）、打印版
