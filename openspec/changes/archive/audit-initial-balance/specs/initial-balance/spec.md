# initial-balance Spec

> **Note（2026-08-26 被 audit-initial-anchor 修正）**：本 spec 中"生效月==当前月"/"首次月==当前月"的调整额触发条件，已按会计专家评审改为"**启动月（建账月）==当前月**"——期初调整只落建账月，`生效月`/`首次月份` 字段降级为信息性，`ensureBackfillForAll` 回填机制删除，`add-manual` 改为幂等更新。详见 openspec/changes/audit-initial-anchor/。

## ADDED Requirements

### Requirement: 期初调整额在生效月生效
`GetInitBalanceForGenerate` 必须把"期初调整额"作为期初来源：手动调整科目在 `生效月==当前月` 且调整额≠0 时，期初=调整额；自动识别科目在 `首次月==当前月` 且调整额≠0 时，期初=调整额。期初调整额是最高优先级来源（优先于上月期末、余额历史、首次记录、0）。

#### Scenario: 手动调整科目在生效月生效
- **WHEN** 科目 X 在 手动调整科目 中配置 `生效月=2026-03, 期初调整额=100000`，生成 2026-03
- **THEN** X 的期初余额 = 100000.00，账页插入摘要"期初余额"的行

#### Scenario: 自动识别科目在首次月生效
- **WHEN** 科目 Y 在 自动识别科目 中配置 `首次月份=2026-02, 期初调整额=5000`，生成 2026-02
- **THEN** Y 的期初余额 = 5000.00

#### Scenario: 手动调整科目调整额为 0 不生效
- **WHEN** 科目 X 在 手动调整科目 中 `调整额=0`，生成生效月
- **THEN** 期初不取调整额，走后续来源（上月期末/余额历史/0）

### Requirement: 生效月之后月份续链，不破坏余额链连续
调整额只在生效月/首次月当月直取；生效月之后的月份，期初必须走上月期末 → 余额历史续链，不得被调整额反复覆盖。

#### Scenario: 生效月后下月续链
- **WHEN** 科目 X 2026-03 生效调整额 100000，且 3 月发生借方 +300
- **THEN** X 2026-04 期初 = 100300（2026-03 期末），而非回到 100000

#### Scenario: 跨年不被调整额覆盖
- **WHEN** 科目 Y 首次月份为 2025-10 且调整额≠0，year-close 后生成 2026-01
- **THEN** Y 2026-01 期初 = 2025-12 期末（prevFinals），不是调整额

### Requirement: 自动识别科目首月净额不进入期初链路
`UpdateBalancesAfterGenerate` 创建新科目时，`首次记录.金额` 恒置 0；首月净发生额不得写入 `首次记录.金额`，不得触发期初回填。

#### Scenario: 新科目首月净额不写首次记录
- **WHEN** 新科目 银行存款 首次出现当月净额为 -118119.59（贷）
- **THEN** `科目树.银行存款.首次记录.金额` = 0，属性按类别推断为"借"，期初不为 -118119.59 污染

### Requirement: 仅手动调整科目允许回填
`ensureBackfillForAll` 只对 `手动调整科目`（调整额≠0）回填 `启动月..生效月-1` 的余额记录；自动识别科目一律不回填。

#### Scenario: 手动调整科目回填
- **WHEN** 手动调整科目 X 生效月 2026-03、调整额 100000、启动月 2026-01
- **THEN** X 的 Balances 在 2026-01..2026-02 被回填（期初=期末=100000）

#### Scenario: 自动识别科目不回填
- **WHEN** 自动识别科目 Y 首月净额≠0（修复前曾回填）
- **THEN** 修复后重跑，Y 不再产生新的回填记录；已有幻影记录被迁移清理

### Requirement: 幻影期初迁移（自愈）
`PurgePhantomInitials(cfg)` 幂等：对 `首次记录.方式=="自动识别"` 的科目，`首次记录.金额` 置 0，并删除 Balances 中 `月份<首次月` 且 `借方==0 && 贷方==0` 的记录。generate 加载 JSON 后自动执行。

#### Scenario: 历史幻影期初被清理
- **WHEN** 银行存款（自动识别，首次月 2025-10）的 Balances 含 2025-01..2025-09 回填记录（无发生额）
- **THEN** 重跑 generate 后这些记录被删除，期初表不再出现幻影余额；真实余额记录不受影响

### Requirement: 科目属性按类别推断
新科目属性按总账科目类别推断：资产/费用→借，负债/权益/收入→贷，未知→借。不得按首月净额推断。用户可 `SetAccountProperty` 覆盖；`check` 对未知类别科目提示。

#### Scenario: 银行存款属性为借
- **WHEN** 银行存款（资产类）首次出现且当月净额为负
- **THEN** 属性 = "借"（按类别），而非按净额推断的"贷"

### Requirement: 期初行摘要按来源区分
账页期初行摘要：期初来源为调整额 → "期初余额"；来源为延续且当月为 1 月 → "上年结转"；其余 → "期初余额"。

#### Scenario: 跨年延续写上年结转
- **WHEN** 2026-01 生成，科目已有 Sheet、期初=2025-12 期末（来源 carryover）
- **THEN** 期初行摘要 = "上年结转"

#### Scenario: 建账/调整期初写期初余额
- **WHEN** 科目新出现或当月有调整额生效（来源 adjustment）
- **THEN** 期初行摘要 = "期初余额"

### Requirement: 中途建账期初行触发
已有 Sheet 的科目，期初≠0 且（当月为 1 月 **或** 当月有调整额生效）→ 插入期初行；原实现仅限 1 月，本次扩展。

> **Note（已知限制）**：中途建账期初行（调整额生效月，非 1 月）当前仅**总分类账（GL）**支持；**多科目明细账（ML）与合并总分类账（MergeGL）对已有 Sheet 的中途补记暂沿用旧余额链**，不插入期初行（跨年 1 月场景三路均正确）。三路中途补记一致化列为后续独立 change。

#### Scenario: 年中补记期初出现期初行
- **WHEN** 科目 X 已有 Sheet，2026-05 配置调整额生效（期初≠0）
- **THEN** 2026-05 账页插入摘要"期初余额"的行

### Requirement: 期初试算平衡校验
`check` 命令校验全体科目最新月份快照的期初 借合计=贷合计，不平报错；`generate` 对当月期初映射校验，不平告警不阻断。

#### Scenario: check 检出期初不平衡
- **WHEN** 最新月份快照期初借方合计 100000、贷方合计 90000
- **THEN** check 报错退出，指出差额

#### Scenario: generate 对期初不平衡告警
- **WHEN** 当月期初映射借≠贷
- **THEN** generate 打印告警但不中断生成

### Requirement: -f 级联重建基线正确
`generate -f` 重建当月时，期初必须来自正确的上月期末/JSON，不得被旧版当月 xlsx 污染；新年首月重建不得复制旧年度 xlsx 明细。

#### Scenario: -f 重建当月不污染期初
- **WHEN** 已存在 2025-10.xlsx（含旧数据），执行 `generate -f` 重建 2025-10
- **THEN** 期初=上月期末（或 0/JSON 余额历史），而非旧版当月的期末

#### Scenario: 跨年首月 -f 重建从空开始
- **WHEN** 执行 `generate -f` 重建 2026-01（year-close 已结转）
- **THEN** 不复制 2025-12 明细，工作薄从空开始，期初=2025-12 期末（取自 JSON）
