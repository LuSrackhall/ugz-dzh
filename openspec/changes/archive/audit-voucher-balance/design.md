## Context

审计 H2：全库无凭证借贷平衡校验，不平衡凭证静默入账（e2e 数据实测累积差额 -15,760.35）。CLI 是绝对安全对象，输入校验必须内建在 generate 中强制执行。

## Goals / Non-Goals

**Goals:**
- generate 前逐张凭证校验借贷平衡（绝对值口径），不平拒绝生成
- 红字明确负数列示 + 提示，不自动折入对侧（折入会破坏绝对值平衡且改变用户数据语义）
- 凭证号未解析条目安全跳过（不误分组）

**Non-Goals:**
- 不改凭证解析器（parseAmountToCents 已处理金额格式与精度）
- 不自动改写用户金额（红字保留原值）
- 不引入新命令（校验内建于 generate）

## Decisions

**D1 带符号净额口径**：`Σ DebitCents == Σ CreditCents`（带符号求和，不取绝对值）。红字（负数）直接参与求和：同侧红字冲抵（贷 -11700 + 贷 +11700 = 0）天然平衡；跨侧红字（借 500 / 贷 -500）净额不等 → 报错（该形态会计上确为不平衡）。实测 e2e 数据"记字第0001号"红字调账凭证（贷 -11700/贷 +11700）即此形态，绝对值口径误报，净额口径正确。

**D2 分组键 = 日期 + 凭证号**：同一凭证的多行分录按（Date, VoucherNum）归组。VoucherNum<=0 的条目（解析失败）单独跳过分组校验并 warning——避免多张无号凭证被误并成一组。

**D3 红字不折入对侧**：审计 H2 给"折入对侧 / 明确负数列示"两个选项。分析表明折入对侧会改变用户数据语义且口径混乱，故选**明确负数列示**：保留负数，warning 提示，账本/汇总显示负金额（审计 L4 打印口径在账本显示层保持一致）。平衡校验用带符号净额口径（D1），无需折入即可正确处理红字。

**D4 校验时点**：`cmd/generate.go` 在 `CollectEntries` 后、写 CSV/XLSX 汇总前调用。error → 拒绝生成（CLI 内建，不靠使用习惯）；warnings → 打印。

## Risks / Trade-offs

- **既有数据可能不平**：若历史凭证存在不平衡，升级后 generate 会拒绝生成——这是预期行为（CLI 安全优先），用户需修正凭证或用历史 xlsx（铁律一：历史文件不重写）。e2e 测试数据如含不平衡凭证将在验收时暴露。
- **绝对值口径 vs 净额口径**：绝对值口径允许红字（更符合会计习惯）；若未来需要"红字折入"须单独设计（改变数据语义，超出本 change）。
