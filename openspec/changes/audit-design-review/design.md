## Context

设计专家审查发现 4 项必须改进，均已复核（官方条文 + 真实数据）。用户授权决策：本批做 4 项；资产负债表/收支结余表拆 Change 10。

## Goals / Non-Goals

**Goals:** 日记账、试算平衡口径、year-close JSON、损益结转草稿。

**Non-Goals:** 资产负债表/收支结余表（Change 10）；日记账打印版（后续）；科目汇总表/凭证序时簿、结账标记、红字口径统一（记录暂缓）。

## Decisions

**D1 日记账数据源**：从当月 entries 筛选 `GeneralAccount=="库存现金"`（现金日记账）与 `GeneralAccount=="银行存款"`（银行日记账，含子科目，按明细分列或合并一行——本批按明细科目分行、同明细排序）。排序键：(Date, VoucherNum, 出现序)。对方科目=同凭证号其他分录的 GeneralAccount 去重 join "、"（超 3 个加"等"）。余额=期初(initials)+逐笔借-贷；日结=相邻日期最后一行后插"本日合计"；月结=本月合计/本年累计/期末结存。现金余额<0 输出 warning。

**D2 期初/期末表借贷分列**：行按 `AccountTypeOf(general)` 归位——资产/费用→借方列；负债/权益/收入→贷方列；未知类别科目按余额符号归位（余额>0 借、<0 贷）。表尾"借方合计/贷方合计/差额"。属性列保留。

**D3 year-close JSON**：year-close 内 `os.ReadFile({year}.json)` → 写 `output/{year+1}/{year+1}.json`（MkdirAll 已有）。复制保留全部配置（期初锚定语义、Balances 历史——H1 同年过滤已处理跨年）。

**D4 结转草稿**：year-close 在损益告警基础上，对每个损益科目输出结转建议行（收入：借余额/贷 本年收益；费用：借 本年收益/贷余额；负数取反向）。"本年收益"为权益类结转目标科目。

## Risks / Trade-offs

- **日记账对方科目**：简化取同凭证对方总账科目（非明细），符合《规范》"对应科目栏只填总账科目"。
- **期初/期末表格式变更**：列结构变化，既有检查脚本/目视习惯需适应（收益：可勾稽）。
- **year-close JSON 复制**：新年 JSON 沿用旧启动月（期初锚定语义）——README 已说明，year-close 提示会再次说明。
