# initial-anchor Spec

## ADDED Requirements

### Requirement: 期初调整只在建账月生效
`GetInitBalanceForGenerate` 仅当 `month == 启动月`（init 的建账月）时直取期初调整额（手动调整科目调整额≠0、自动识别科目调整额≠0）；其余月份一律走上月期末 → 余额历史续链，调整额不参与。

#### Scenario: 建账月期初=调整额
- **WHEN** 科目 X 手动调整额 100000，启动月 2025-10，生成 2025-10
- **THEN** X 期初=100000，账页首行摘要"期初余额"

#### Scenario: 非建账月续链不读调整额
- **WHEN** 生成 2025-11（非启动月），X 有上月期末 100300
- **THEN** X 期初=100300（上月期末续链），不是 100000

#### Scenario: 中途补期初经 -f 重建落建账月
- **WHEN** 账记到 2026-05，发现 X 建账月期初写错，改调整额后 `generate -f` 从 2025-10 重建
- **THEN** 重建时 2025-10 期初=新调整额，2025-11..2026-05 逐月续链重算

### Requirement: 生效月字段废弃（信息性）
`手动调整科目[].生效月` 与 `自动识别科目[].首次月份` 保留在 JSON（兼容旧数据、记录时点信息），**不参与期初计算**。

#### Scenario: 生效月不影响计算
- **WHEN** 手动调整科目 X 生效月字段为 2026-03（旧数据），生成 2026-03
- **THEN** X 期初=2026-02 期末（续链），生效月不生效

### Requirement: add-manual 幂等更新
`add-manual` 对同科目重复调用 → 更新调整额/说明（修正建账月期初值），不报错；无则新增。

#### Scenario: 修正期初值
- **WHEN** 先 add-manual X 100000，再 add-manual X 150000
- **THEN** 第二次不报错，X 调整额更新为 150000
