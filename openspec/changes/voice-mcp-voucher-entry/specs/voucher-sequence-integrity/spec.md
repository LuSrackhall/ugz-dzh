# voucher-sequence-integrity（新增）

## ADDED Requirements

### Requirement: 凭证号连续性检查

系统 SHALL 提供凭证序列完整性检查，对目标月目录内的凭证 md 解析凭证号，判定：号码是否连续（1..N 无缺）、是否重复、张数是否与唯一号个数自洽。

检查 MUST 只读取文件，MUST NOT 修改任何凭证文件或账本产物。

#### Scenario: 连续无重通过

- **WHEN** 月目录内为 `记字第0001号.md` 至 `记字第0025号.md`，无缺号无重号
- **THEN** 检查报告通过，并输出张数 25

#### Scenario: 断码被识别

- **WHEN** 月目录内有 0001..0012 与 0014..0025（缺 0013）
- **THEN** 检查报告缺号 0013，并提示由用户决策（补录或确认作废留空）

#### Scenario: 重号被识别

- **WHEN** 月目录内两个文件解析出同一凭证号
- **THEN** 检查报告该号重复，并列出涉及的文件名

### Requirement: 月目录白名单检查

检查 SHALL 判定目标月目录内所有 `.md` 文件是否都匹配正式凭证命名 `记字第<数字>号.md`。任何不匹配的 `.md` MUST 被列出，包括文件名不可解析凭证号者与带额外后缀者。

该项为必要防护：凭证收集走 `filepath.WalkDir` 递归（`cmd/common.go:34`），月目录内任何 `.md` 都会被解析记账，而重号检测基于文件名正则（`cmd/generate.go:386`），不含"记字第"的文件名连告警都不会产生。

#### Scenario: 非凭证 md 被列出

- **WHEN** 月目录内存在 `草稿.md` 与 `模板.md`
- **THEN** 检查列出这两个文件为非正式凭证文件
- **AND** 说明它们会被递归解析并计入账本

#### Scenario: 带后缀的凭证文件被列出

- **WHEN** 月目录内存在 `记字第0005号 更正.md`
- **THEN** 检查列出该文件不符合正式命名规范

### Requirement: 默认告警、`--strict` 才阻断

序列完整性与白名单检查 SHALL 默认只输出告警并以零码退出；仅在显式传入 `--strict` 时以非零码退出。`voucher add` 的写入前置检查 MUST 使用相同的默认告警口径（列出问题但不阻断）。

此口径为兼容铁律一（历史文件永不修改）：真实历史账套可能存在作废留空号或带后缀的文件名，若默认阻断将使这些账套无法继续生成。

#### Scenario: 默认模式不阻断

- **WHEN** 对存在断码的历史账套执行检查（不带 `--strict`）
- **THEN** 命令输出问题清单
- **AND** 退出码为 0

#### Scenario: strict 模式阻断

- **WHEN** 对存在断码的账套执行检查并带 `--strict`
- **THEN** 命令以非零码退出

#### Scenario: 检查结果可供 agent 结构化消费

- **WHEN** 检查以结构化输出模式运行
- **THEN** 输出包含问题类别（缺号/重号/非正式文件名）、涉及文件名与凭证号
- **AND** 输出可直接作为 agent 向用户复述与请求决策的输入
