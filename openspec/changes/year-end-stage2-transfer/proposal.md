# 年末二段结转：本年收益 → 收益分配

## Why

财会〔2023〕14号 年末损益结转制度上分三段：① 收入/费用 → 本年收益（gen-close 已实现）；② **本年收益 → 收益分配——未分配收益（净亏损方向相反）——未实现（本变更）**；③ 各项分配互转（次年分配方案动作，不在本期）。

二段缺失的后果：上年净收益以"本年收益"期初滞留带入新年（e2e 演示账套实测 2026-01 期初 = 2025 净收益 263 万贷余）；次年年结时两年净收益混在同一科目，"本年收益"失去年度语义。

## What Changes

1. **gen-close 追加二段凭证**：第一段凭证生成后，对"本年收益"当期余额（第一段并入后的重算值，非 JSON 旧值）追加一张凭证：
   - 贷余（净收益）：借 本年收益 / 贷 结转目标科目；
   - 借余（净亏损）：借 结转目标科目 / 贷 本年收益；
   - 金额=|余额|；摘要"年末收益结转"；同批写入 `{year}/closing/`，日期与第一段一致，编号顺延。
2. **防重独立口径**：第一段凭证本身含"本年收益"分录，不能沿用"科目出现过即跳过"。二段用独立判定：`closing/` 尚无含收益分配分录的凭证（hasTransfer）且 重算后本年收益余额≠0。
3. **结转目标科目自动登记**（先定义后生成自洽，属性=贷，参照"本年收益"预登记模式）。
4. **资产负债表权益列口径确认**：现行 writeBalanceSheet 代码推演零改动即正确（已结转月收益分配入权益列、未结转月照旧"本年收益（未结转损益）"行、混合年两行并存），以 e2e 断言固化，不改代码。
5. **附带小修**：AGENTS.md 1.4 关于 year_close.go 写 "A1/G1" 的过时描述更正；技能双目录文档同步（gen-close 行为、权益列口径、年末流程顺序）。

## Impact

- **代码**：`cmd/gen_close.go`（主体，抽出可单测的纯函数）；`generator/` 零改动；`cmd/year_close.go` 零改动。
- **文档**：`AGENTS.md`；`.agents/skills/ledger-accounting/` 与 `embedded/ledger-accounting/` 双目录逐字同步（embed_test.go 守护）。
- **兼容**：老账套无需回溯重建（历史月铁律一不动）；下游升级后第一次年结跑新版 gen-close 即自愈（详见 design.md D2 中间态推演）。
